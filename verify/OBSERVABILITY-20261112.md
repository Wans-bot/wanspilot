# 1.3.0 日历统计、订阅过程与登录视觉

日期：2026-11-12

## 实际问题与修复

经用户授权登录 NAS，只读检查订阅、日志、日历和 TMDB 季数据。发现一部订阅实际已播 656 集，下载记录为 0，旧日历只统计当月 3 集，旧检查结束后却显示“已是最新”。生产账号、密码、Cookie、密钥均不保存到仓库或验收材料。未执行生产搜索、下载、暂停、删除、改设置或重建容器。

修复统计范围：累计所有剧集订阅（包括暂停的订阅）选定季内全部已播缺集，无指定季则取所有正季；下载中和未播出排除。月份只限制月历。待补集指标可切换完整跨月时间线，TMDB 部分失败显示 ≥ 与警告，不能冒充完整数字。

修复后台透明度：订阅创建和每次检查、读取季、搜索范围/候选数、未匹配原因、提交、成功、完成、错误和调度均记录。每部保留最近 100 条并落盘，重启时中断工作可恢复调度；前端每 3 秒刷新状态，提供记录弹窗和真实关联 qB 任务，不把提交当完成。手动检查 HTTP 202 立即返回，避免长搜索时前端等到超时。

修复长剧无资源死循环：每轮最多尝试五个单集/提交一个整季包，最多 12 个实际查询，90 秒后不发新查询（在途请求仍按自身超时）；记录游标轮换，未匹配不能再报告已是最新。先统计全部季已播数，搜索额度不会截断总数。

运行日志覆盖业务操作而非静态资源/轮询噪声，恢复落盘记录，4 MiB 轮转保留一份旧文件，界面最近 1000 行自动刷新、筛选、导出最近 2000 行。凭据脱敏，不记录请求体。有限保留，不宣称无限历史。

登录页本地 SVG 插画，桌面双栏与手机纵向排布，账号/密码图标，透明 Logo，深浅主题适配。禁止装饰性彩色边条。

## 验证

- 64 项后端测试通过：跨月/全季/暂停订阅统计，未播出与下载中排除、失败恢复、长剧无资源分页轮换、全源失败、运行中暂停不提交、异步检查、过程可见与落盘、日志恢复/脱敏、业务操作覆盖；原 qB 协议兼容与 API 回归保留。
- 71 项浏览器检查通过，包含完整缺集时间线、搜索到下载的动态刷新、过程弹窗、日志自动加载/刷新/筛选、SVG 与表单图标、手机过程弹窗及登录短屏/横屏。
- 深浅主题 × 7 视口 × 13 页面 = 182 组布局检查通过。
- npm run check 与 git diff --check 通过。
- 截图与结果：verify/observability-v1。功能回归使用独立临时服务和模拟 API，不提交生产下载；人工查看桌面/手机登录、订阅与记录弹窗。

## 发布

版本 1.3.0，沿用 main → GHCR latest 的双架构发布流程，实际发布结果由工作流和镜像摘要另行核验。NAS YAML 不变。旧版未记录的操作无法凭空补齐；更新后的过程从下一次检查开始记录。
